01 / 实际问题

下载工具真正难的，是中途不出错

普通链接保存只覆盖最理想的一步。真实使用中还会遇到格式分离、流媒体分片、网络中断、任务恢复、音频提取和完成后的文件管理，这些环节决定了工具是否可靠。

02 / 我的职责

从下载引擎，做到工作台与命令行

我完成 React 工作台、Express 本地服务、直链与 HLS 下载、任务状态持久化、FFmpeg 处理、资料库和 CLI，并用真实媒体与受控弱网服务完成端到端验收。

03 / 解决流程

围绕可恢复的任务，而不是一次性请求

  • 先解析来源与格式，再创建带目录、引擎和断点信息的本地任务。
  • 直链按 Range 分段，HLS 逐片保存；暂停和重启后从已有数据继续。
  • 完成后自动封装、提取或写入资料库，并让网页和 CLI 共享同一份状态。
04 / 技术实现

本地优先，但能力完整

  • React + Vite：暖白与陶土色工作台、实时进度、封面取色和响应式布局。
  • Node.js + Express：任务队列、SSE 状态同步、Range 媒体播放和 CLI 服务。
  • 直链 / HLS 引擎：多连接、分片续传、AES-128 与直播停止保存。
  • yt-dlp + FFmpeg：站点解析、音频提取、合流封装与基础元数据。
05 / 成果数据

每一项能力，都用真实文件验证

公开 MP4 与源文件 SHA-256 完全一致；11 MB 文件多连接暂停续传成功；HLS 五分片、直播保存和 192 kbps MP3 均通过解码；桌面与 390px 移动端完成浏览器验收。
